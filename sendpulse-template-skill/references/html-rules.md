## 1. Document Shell

Output a **complete, valid HTML email document**: `<!DOCTYPE html>`, `<html>`, `<head>` (meta tags + the `<style>` blocks), and `<body>` holding the layout (`<div>` wrapper → tables). This matches SendPulse's own exported templates and uploads cleanly via **Upload a file** / MCP / API. (SendPulse's **Insert code** editor also tolerates a body-only fragment — meta tags wrapped in `<p>`, `<style>` then the layout `<div>`, no `<head>`/`<body>` — but the full document is the default and previews correctly on its own.)

---

**R1.1 — Meta Tags** [MANDATORY]

Two meta tags must appear at the top. The charset meta prevents encoding-related rendering bugs in older clients. The viewport meta enables responsive scaling on iOS.

```html
<meta content="text/html; charset=UTF-8" http-equiv="Content-Type" />
<meta content="width=device-width, initial-scale=1.0" name="viewport" />
<title></title>
```

Place these in the document `<head>`, together with the `<style>` blocks. (Only if you deliberately ship a body-only fragment for the *Insert code* editor do they sit inline wrapped in `<p>` — an editor artifact; that path is valid but not the default.)

---

**R1.2 — Two Separate `<style>` Blocks** [MANDATORY]

Every template contains exactly two `<style type="text/css">` blocks in sequence.

**Block 1** — Minimal mobile-hide utility (kept separate for legacy reasons):

```html
<style type="text/css">
  @media only screen and (max-width: 640px) {
    .sp-hidden-mob {
      display: none !important;
    }
  }
</style>
```

---

**R1.3 — Outer Wrapper Element** [MANDATORY]

The email body starts with a `<div>` (14 of 15 templates) or directly a `<table>` (1 template: digest). The `<div>` carries both `bgcolor` and `background-color` in sync for the page-level background color:

```html
<div
  bgcolor="#eeeeee"
  style="font-size:14px; line-height:1.5; background-color:#eeeeee"
>
  <!-- wrapper-table goes here -->
</div>
```

## 2. Layout Architecture

All layout is built exclusively with `<table>` elements. There are no `<div>`-based columns, no flexbox, no CSS grid. This is required for correct rendering in Outlook, which does not support modern CSS layout models.

---

**R2.1 — Full-Width Outer Wrapper Table** [MANDATORY]

The outermost table stretches to 100% of the viewport and centers the content column:

```html
<table
  border="0"
  cellpadding="5"
  cellspacing="0"
  class="wrapper-table"
  style="border-collapse:collapse; font-size:14px; line-height:1.5; background-repeat:no-repeat"
  width="100%"
>
  <!--[if gte mso 9]><v:background xmlns:v="urn:schemas-microsoft-com:vml" fill="t">
    <v:fill type="frame" color="#eeeeee"/>
  </v:background><![endif]-->
  <tbody>
    <tr style="border-color:transparent">
      <td
        align="center"
        style="border-collapse:collapse; border-color:transparent"
      >
        <!-- bodyTable goes here -->
      </td>
    </tr>
  </tbody>
</table>
```

Note: `cellpadding="5"` on the wrapper-table (not `"0"`) is intentional — it creates a small visible gutter around the email body on very narrow screens. Only the `wrapper-table` uses `cellpadding="5"`; all inner tables use `cellpadding="0"`.

---

**R2.2 — Body Table: Fixed for Outlook, Fluid Everywhere Else** [MANDATORY]

The content column is a centered table. Declare a fixed pixel `width` **attribute** for Outlook, and a
fluid **inline style** (`width:100%; max-width:Npx`) so the body shrinks to the viewport on its own —
without depending on a media query (see R3.0):

```html
<table
  bgcolor="#ffffff"
  border="0"
  cellpadding="0"
  cellspacing="0"
  id="bodyTable"
  style="border-collapse:collapse; font-size:14px; line-height:1.5; width:100%; max-width:600px"
  width="600"
></table>
```

Use the numeric form in the `width` attribute (`width="600"`, not `"600px"`). Standard widths:

- `600px` — default for most templates (12 of 15)
- `700px` — wide templates with 2-column image layouts (2 of 15)
- `550px` — narrow, single-column promotional (1 of 15)

> Legacy note: the original 15 templates used `width="600px"` with no inline `max-width` and relied on
> `@media{table{width:100%}}` to go fluid. Prefer the inline `max-width` form above — it survives
> `<style>` stripping in the Gmail app. Keep the media-query rule too, as harmless reinforcement.

---

**R2.3 — Section-per-Table Block Pattern** [MANDATORY]

Each visual section (hero, content block, CTA band, footer) is its own `<table width="100%">` stacked inside the main body `<td>`. Never merge sections into a single table — isolation ensures correct `bgcolor` per section and clean mobile reflow.

```html
<!-- Section 1: preheader / nav band -->
<table
  border="0"
  cellpadding="0"
  cellspacing="0"
  style="border-collapse:collapse; font-size:14px; line-height:1.5; width:100%"
  width="100%"
>
  <tbody>
    <tr style="border-color:transparent">
      <td
        bgcolor="#333333"
        style="background-color:#333333; padding-left:0; ..."
      >
        ...
      </td>
    </tr>
  </tbody>
</table>

<!-- Section 2: hero -->
<table border="0" cellpadding="0" cellspacing="0" ...>
  ...
</table>
```

---

**R2.4 — Column Layout Using `<th>` Elements** [LEGACY — prefer R3.0]

> **Use the fluid-hybrid columns in R3.0 instead for anything that must stack on mobile.** The
> `<th class="tc responsive">` pattern below stacks only via a media query, so it fails in the Gmail
> app (renders side-by-side on a phone). It is documented here because the 15 reference templates use
> it; only choose it for rows that are intended to stay side-by-side on every screen (`tc
no-responsive`), or when you also provide the R3.0 inline fallback.

Multi-column sections (legacy approach) use `<th>` (not `<td>`) as column containers. Each column `<th>` carries `class="tc responsive"`, an explicit pixel `width`, `align="left"`, and `font-weight:400` to suppress bold inheritance:

```html
<tr style="border-color:transparent">
  <th
    align="left"
    cellpadding="0"
    cellspacing="0"
    class="tc responsive "
    style="border-color:transparent; text-align:left; font-weight:400; vertical-align:top"
    valign="top"
    width="350"
  >
    <!-- left column content -->
  </th>
  <th
    align="left"
    cellpadding="0"
    cellspacing="0"
    class="tc responsive "
    style="border-color:transparent; text-align:left; font-weight:400; vertical-align:top"
    valign="top"
    width="350"
  >
    <!-- right column content -->
  </th>
</tr>
```

For full-width single-column blocks use `<th width="[bodyTableWidth]">`.

---

**R2.5 — Content Block Inner Nesting Structure** [MANDATORY]

Inside each `<th>`, content lives in a 3-table deep structure:

```
th.tc → table (border-radius wrapper) → tr → td (valign wrapper)
      → table.wout_block_* (background + overflow:hidden) → tr.content-row → td.content-cell
```

The `content-row` `<tr>` carries inline `color` and `font-family` that cascade to children. The `content-cell` `<td>` holds the actual content.

```html
<th class="tc responsive " width="600" ...>
  <table
    border="0"
    cellpadding="0"
    cellspacing="0"
    style="border-collapse:collapse; ...; border-radius:0"
    width="100%"
  >
    <tbody>
      <tr style="border-color:transparent">
        <td
          cellpadding="0"
          cellspacing="0"
          style="border-collapse:collapse; border-color:transparent; vertical-align:top"
          valign="top"
        >
          <table
            cellpadding="0"
            cellspacing="0"
            id="wout_block_N_element_0"
            style="border-collapse:separate; overflow:hidden; ..."
            width="100%"
          >
            <tbody>
              <tr
                class="content-row"
                style='border-color:transparent; color:#333333;
                         font-family:Arial, "Helvetica Neue", Helvetica, sans-serif'
              >
                <td
                  class="content-cell"
                  style="border-collapse:collapse; border-color:transparent; vertical-align:top;
                           padding-left:20px; padding-right:20px;
                           padding-top:20px; padding-bottom:20px"
                  valign="top"
                  width="560"
                >
                  <!-- actual content: <p>, <img>, button table, etc. -->
                </td>
              </tr>
            </tbody>
          </table>
        </td>
      </tr>
    </tbody>
  </table>
</th>
```

---

**R2.6 — Table Attribute Baseline** [MANDATORY]

Every structural table must carry:

```html
<table
  border="0"
  cellpadding="0"
  cellspacing="0"
  style="border-collapse:collapse; ..."
></table>
```

`border-collapse:collapse` must appear in both the HTML attribute domain (implicit via stylesheet) and inline style because some clients ignore stylesheets. Exception: the `wrapper-table` uses `cellpadding="5"`.

---

**R2.7 — `border-color:transparent` on Every `<tr>`** [MANDATORY]

```html
<tr style="border-color:transparent"></tr>
```

Without this, some clients render a default 1px border between rows.

## 3. Responsive Techniques

SendPulse uses a **single breakpoint at 640px** to switch from fixed-width desktop to fluid mobile. No intermediate breakpoints exist.

---

**R3.0 — Media-Query-Independent Responsiveness** [MANDATORY — IMPORTANT]

> **This rule overrides the media-query-based collapse in R3.2–R3.4 as the _primary_ mechanism.**
> The 15 reference templates stack columns with `@media` + `tc responsive`. Real-world testing shows
> this is fragile: the **Gmail app** (and any client that strips `<style>` or only honors CSS placed
> in `<head>`) drops those media queries, and the email then renders the **full desktop layout on a
> phone** — fixed-width body, side-by-side columns, horizontal scroll. The Gmail app strips `<style>`
> wherever it sits (`<head>` or body), so this failure is common even in a full HTML document.

**Therefore: every responsive behavior must work with all `<style>` blocks removed.** Build the layout
on inline styles that no client strips, and treat `@media` as a _progressive-enhancement_ layer only.

Two load-bearing techniques:

**(a) Fluid body — shrink `bodyTable` with an inline `max-width`, not a media query.**

```html
<table
  bgcolor="#ffffff"
  border="0"
  cellpadding="0"
  cellspacing="0"
  id="bodyTable"
  style="border-collapse:collapse; background-color:#ffffff; width:100%; max-width:600px"
  width="600"
></table>
```

`width:100%; max-width:600px` (inline) makes the body shrink to the viewport in every client on its
own; `width="600"` keeps Outlook at a fixed 600px. Never depend on `@media{table{width:100%}}` alone.

**(b) Fluid-hybrid columns — `inline-block` + `max-width` + MSO ghost tables.**

Columns reflow purely from available width: when the viewport is narrower than the sum of the column
`max-width`s, the blocks wrap to one-per-row. No media query is involved, so it survives stripping.
Outlook (which ignores `inline-block`) is held side-by-side by `<!--[if mso]>` ghost-table cells.

```html
<table
  border="0"
  cellpadding="0"
  cellspacing="0"
  style="border-collapse:collapse; width:100%"
  width="100%"
>
  <tbody>
    <tr style="border-color:transparent">
      <td
        align="center"
        style="border-collapse:collapse; border-color:transparent; padding-left:20px; padding-right:20px; padding-top:0; padding-bottom:0"
      >
        <div style="font-size:0; line-height:0; text-align:center;">
          <!--[if mso]><table role="presentation" border="0" cellpadding="0" cellspacing="0" width="560" align="center"><tr><td width="280" valign="top"><![endif]-->

          <!-- Column 1 -->
          <div
            class="hcol"
            style="display:inline-block; width:100%; max-width:280px; vertical-align:top; font-size:14px; line-height:1.5; text-align:left;"
          >
            <div
              style="padding-left:10px; padding-right:10px; padding-top:0; padding-bottom:24px;"
            >
              <!-- card / image / text -->
            </div>
          </div>

          <!--[if mso]></td><td width="280" valign="top"><![endif]-->

          <!-- Column 2 -->
          <div
            class="hcol"
            style="display:inline-block; width:100%; max-width:280px; vertical-align:top; font-size:14px; line-height:1.5; text-align:left;"
          >
            <div
              style="padding-left:10px; padding-right:10px; padding-top:0; padding-bottom:24px;"
            >
              <!-- card / image / text -->
            </div>
          </div>

          <!--[if mso]></td></tr></table><![endif]-->
        </div>
      </td>
    </tr>
  </tbody>
</table>
```

Notes:

- `font-size:0; line-height:0` on the wrapper removes the whitespace gap between `inline-block` blocks; each block restores `font-size:14px`.
- The visual gutter is the inner `padding-left/right` on each block (not margins), so it stays even on mobile.
- For a 2×2 grid, place four blocks in one wrapper and give the MSO ghost table two `<tr>` rows.
- Images inside use `width:100%` (+ `class="p100_img"`) so they fill the block at any width.

**Optional enhancement (media query):** to make the wrapped blocks go _full width_ on phones (instead
of staying at their `max-width`), add — as a bonus, never as the load-bearing mechanism:

```css
@media only screen and (max-width: 640px) {
  .hcol {
    max-width: 100% !important;
    width: 100% !important;
  }
}
```

**Self-test:** delete both `<style>` blocks, open at ~375px wide — the email must already be a single
clean column with no horizontal scroll. If it isn't, the layout is leaning on media queries; fix it.

**R3.1 — Single Mobile Breakpoint** [MANDATORY]

```css
@media only screen and (max-width: 640px) {
  /* mobile overrides */
}
```

Always use exactly `640px`. This breakpoint appears three times in the `<style>` block covering different rule groups.

---

**R3.2 — Column Collapse via `display:block`** [MANDATORY]

All `<td>` and `<th>` switch to `display:block` on mobile, stacking columns vertically:

```css
@media only screen and (max-width: 640px) {
  td,
  th {
    display: block !important;
    margin-bottom: 0;
    height: inherit !important;
  }
  table,
  hr {
    width: 100%;
    max-width: 100% !important;
  }
  td,
  div {
    width: 100% !important;
    height: auto !important;
    box-sizing: border-box;
  }
}
```

---

**R3.3 — `tc responsive` Class — Column Collapse Signal** [MANDATORY]

Columns marked `class="tc responsive"` collapse to full width on mobile via:

```css
.tc.responsive,
td.content-cell > p,
th.content-cell > p {
  width: 100% !important;
}
```

Columns marked `class="tc no-responsive"` maintain side-by-side layout on mobile.

---

```css
@media only screen and (max-width: 640px) {
  td.content-cell,
  th.content-cell {

  }
}
```

## 4. Outlook Compatibility (MSO)

Outlook on Windows uses the Word rendering engine, which ignores `border-radius`, has limited `background-image` support, and does not treat `display:block` on table cells the same as modern browsers.

---

**R4.1 — VML Background Fallback** [MANDATORY]

When a table has a `background` image attribute, add a VML comment immediately inside the `<table>` for Outlook:

```html
<table
  background="https://cdn.sendpulse.com/bg.png"
  bgcolor="#eeeeee"
  border="0"
  cellpadding="5"
  cellspacing="0"
  class="wrapper-table"
  width="100%"
>
  <!--[if gte mso 9]>
    <v:background xmlns:v="urn:schemas-microsoft-com:vml" fill="t">
      <v:fill
        type="frame"
        color="#eeeeee"
        src="https://cdn.sendpulse.com/bg.png"
      />
    </v:background>
  <![endif]-->
  <tbody>
    ...
  </tbody>
</table>
```

For color-only backgrounds (no image), omit `src`:

```html
<!--[if gte mso 9]>
  <v:background xmlns:v="urn:schemas-microsoft-com:vml" fill="t">
    <v:fill type="frame" color="#ffffff" />
  </v:background>
<![endif]-->
```

---

**R4.2 — MSO Table Spacing Reset** [MANDATORY]

```css
table,
td {
  mso-table-lspace: 0;
  mso-table-rspace: 0;
}
```

Removes Outlook's default table cell spacing.

---

**R4.3 — Outlook Link Padding Reset** [MANDATORY]

```css
#outlook a {
  padding: 0;
}
```

Outlook adds default padding to links inside cells. Reset it globally.

---

**R4.4 — `[if !mso]><!-->`...`<!--<![endif]-->` Pattern** [MANDATORY]

Used to show mobile-specific content in all clients except Outlook. Outlook processes MSO conditional comments but ignores content between `<!--` and `-->`:

```html
<!-- Desktop image (visible everywhere including Outlook) -->
<img
  src="desktop.jpg"
  class="desktop sp-img"
  width="600"
  height="auto"
  border="0"
  alt=""
  style="height:auto; line-height:100%; outline:0; text-decoration:none;
            border:0; display:block; -ms-interpolation-mode:bicubic"
/>

<!--[if !mso]><!-->
<!-- Mobile image DIV (hidden from Outlook by the conditional comment) -->
<div style="font-size:14px; line-height:1.5; mso-hide:all">
  <img
    src="mobile.jpg"
    class="mobile sp-img"
    width="100%"
    height="0"
    border="0"
    alt=""
    style="height:0; line-height:100%; outline:0; text-decoration:none; border:0;
              display:block; -ms-interpolation-mode:bicubic;
              max-height:0; overflow:hidden; width:100%; max-width:600px !important"
  />
</div>
<!--<![endif]-->
```

---

**R4.5 — `mso-hide:all`** [MANDATORY]

Any element that must be invisible to Outlook's Word renderer (secondary insurance beyond conditional comments):

```html
<div style="mso-hide:all; font-size:14px; line-height:1.5">
  <!-- not rendered by Outlook -->
</div>
```

---

**R4.6 — Bullet List Fix for Outlook** [RECOMMENDED]

```css
ul > li {
  mso-special-format: bullet;
}
```

---

**R4.7 — No VML Buttons** [INFORMATIONAL]

SendPulse templates do NOT use VML for rounded buttons. Buttons are pure CSS tables — Outlook renders them with square corners, which is the accepted behavior. Do not add VML button fallback markup.

## 5. Typography

Font declarations must be defensive: always end every font stack with a guaranteed fallback. All font sizes are in `px` only.

---

**R5.1 — Font Size Units: `px` Only** [MANDATORY]

Never use `em`, `rem`, `pt`, or `%` for font sizes.

Common scale:

- Body text: `14px` (default), `15px`, `16px`
- Captions / legal: `12px`, `13px`
- Subheadings: `18px`, `20px`
- Headings: `24px`, `30px`, `36px`
- Hero display: `48px`, `120px`

---

**R5.2 — Font Family Stacks** [MANDATORY]

**Stack 1 — Classic sans-serif** (most common, ~60% of templates):

```css
font-family: Arial, "Helvetica Neue", Helvetica, sans-serif;
```

**Stack 2 — Modern sans-serif** (newer designs, ~30% of templates):

```css
font-family:
  "Helvetica Neue", Helvetica, "Neue Haas Grotesk Text Pro", Arial, sans-serif;
```

**Stack 3 — Serif** (luxury / editorial templates):

```css
font-family: Georgia, "Times New Roman", Times, serif;
```

**Stack 4 — Windows-centric** (black-friday template only):

```css
font-family: "Segoe UI", Segoe, "Avenir Next", "Open Sans", Corbel, sans-serif;
```

---

**R5.3 — Dual Font Declaration** [MANDATORY]

Declare `font-family` and `color` in two places per block:

1. On `<tr class="content-row">` — cascades to children
2. On every `<p>`, `<td>`, `<a>` that displays text — explicit override

```html
<tr
  class="content-row"
  style='border-color:transparent; color:#333333;
           font-family:Arial, "Helvetica Neue", Helvetica, sans-serif'
>
  <td class="content-cell" style="...">
    <p
      style='font-size:inherit; line-height:inherit; margin:0 0 10px;
              color:#333333; font-family:Arial, "Helvetica Neue", Helvetica, sans-serif;
              font-weight:normal; padding:0'
    >
      Text here.
    </p>
  </td>
</tr>
```

Note: `font-size:inherit` and `line-height:inherit` on `<p>` are intentional — values cascade from the parent `<td>`.

---

**R5.4 — No Web Fonts** [MANDATORY]

Zero of 15 templates load external fonts via `@font-face`, Google Fonts, or CDN. Do not add web font loading.

---

**R5.5 — Line Height** [MANDATORY]

- Body text: `line-height: 1.5` (unitless)
- Headings: `line-height: 1.2`
- Button link text: `line-height: 1`
- Social icon cells: `line-height: 32px`

---

**R5.6 — Heading Font Weight Reset** [RECOMMENDED]

The global reset sets `h1`–`h5` to `font-weight:400`. Use `<strong>` or explicit `font-weight:bold` override when bold headings are needed.

## 6. Color & Backgrounds

Always declare color in both the legacy HTML attribute and the CSS inline style. Never rely on only one.

---

**R6.1 — Dual Color Declaration** [MANDATORY]

Every background color must appear twice: `bgcolor` attribute + `background-color` style. Values must match.

```html
<!-- On <div> wrapper -->
<div bgcolor="#eeeeee" style="background-color:#eeeeee; ...">
  <!-- On <table> -->
  <table bgcolor="#ffffff" style="background-color:#ffffff; ...">
    <!-- On <td> -->
    <td
      bgcolor="#f9f9f9"
      style="background-color:#f9f9f9; padding-left:0; ..."
    ></td>
  </table>
</div>
```

---

**R6.2 — 6-Digit Hex in Inline Styles** [MANDATORY]

Use `#ffffff` not `#fff` in `style=""` attributes. 3-digit hex in inline styles is not supported by some clients. 3-digit hex is acceptable in `<style>` blocks.

---

**R6.3 — Background Image on `<td>`** [RECOMMENDED]

```html
<td
  background="https://cdn.sendpulse.com/path/bg.png"
  bgcolor="#eeeeee"
  style="background-color:#eeeeee; background-position:center top; background-repeat:no-repeat; ..."
></td>
```

The `bgcolor` / `background-color` fallback displays when images are blocked.

---

**R6.4 — No CSS Gradients** [MANDATORY]

Gradients are implemented as image files. Do not use `linear-gradient` or `radial-gradient` — they are not supported in Outlook.

---

**R6.5 — Color Inheritance Override for Gmail** [MANDATORY]

Include in the global `<style>` block:

```css
.content-cell em,
.content-cell span[style*="color"] > a,
.email-wrapper span[style*="color"] > a {
  color: inherit;
}
```

This prevents Gmail from overriding link colors inside colored `<span>` elements.

## 7. Images

Every image attribute is load-bearing in email. Omitting any of the required attributes causes rendering bugs in at least one major client.

---

**R7.1 — Required Image Attributes** [MANDATORY]

```html
<img
  src="https://s[id].sendpul.se/files/.../image.png"
  alt="Description"
  border="0"
  width="600"
  height="auto"
  style="height:auto; line-height:100%; outline:0; text-decoration:none;
         border:0; display:block; -ms-interpolation-mode:bicubic"
/>
```

- `border="0"` — removes IE border on linked images
- `width="[px]"` — exact pixel width; ensures correct Outlook rendering
- `height="auto"` — prevents distortion during scaling
- `display:block` — eliminates the inline-element gap below images in table cells
- `outline:0` — removes Outlook focus ring
- `line-height:100%` — prevents Gmail from adding space below images
- `-ms-interpolation-mode:bicubic` — improves scaling quality in older IE/Outlook

---

**R7.2 — Desktop / Mobile Image Dual Pattern** [MANDATORY]

When an image needs different treatment on mobile, use this exact pattern:

```html
<!-- Desktop: visible in ALL clients including Outlook -->
<img
  src="desktop.jpg"
  class="desktop sp-img"
  width="600"
  height="auto"
  border="0"
  alt=""
  style="height:auto; line-height:100%; outline:0; text-decoration:none;
            border:0; display:block; -ms-interpolation-mode:bicubic"
/>

<!--[if !mso]><!-->
<div style="font-size:14px; line-height:1.5; mso-hide:all">
  <!-- Mobile: hidden from Outlook, toggled by CSS -->
  <img
    src="mobile.jpg"
    class="mobile sp-img"
    width="100%"
    height="0"
    border="0"
    alt=""
    style="height:0; line-height:100%; outline:0; text-decoration:none;
              border:0; display:block; -ms-interpolation-mode:bicubic;
              max-height:0; overflow:hidden; width:100%; max-width:600px !important"
  />
</div>
<!--<![endif]-->
```

CSS in `<style>` block that drives the toggle:

```css
img.sp-img.mobile {
  display: none;
} /* default: mobile hidden */

@media only screen and (max-width: 640px) {
  img.sp-img.desktop {
    display: none !important;
    height: 0 !important;
    max-height: 0 !important;
    overflow: hidden !important;
  }
  img.sp-img.mobile {
    display: block !important;
    height: auto !important;
    max-height: none !important;
    overflow: visible !important;
  }
}
```

---

**R7.3 — Absolute HTTPS Image URLs** [MANDATORY]

All `src` values use full absolute HTTPS URLs. Never use relative paths.

```
https://s[accountID].sendpul.se/files/emailservice/userfiles/[hash]/[folder]/[file.ext]
```

---

**R7.4 — `img-wrap` Container** [RECOMMENDED]

Wrap images in a `div.img-wrap` with explicit dimensions:

```html
<div
  align="center"
  class="img-wrap"
  height="300"
  width="100%"
  style="font-size:14px; line-height:1.5; width:100%; height:300;
            display:block; text-align:center"
>
  <center>
    <img ... />
  </center>
</div>
```

The `<center>` tag is a legacy centering fallback for old clients.

---

**R7.5 — No Retina / HiDPI Techniques** [INFORMATIONAL]

None of the templates use `srcset`, half-size `width`/`height` attributes, or `@2x` patterns. Images are served at 1× density. This is the established SendPulse approach.

---

**R7.6 — Alt Text on All Images** [MANDATORY]

Every `<img>` must have `alt`. Use descriptive text for content images; use `alt=""` for decorative images. Never omit the attribute.


**R8.6 — Multi-Button Rows (Fluid Hybrid, Stack on Mobile)** [MANDATORY]

`tc responsive` table cells — so it reflows to one button per row on phones **without a media query**

## 9. Spacing

Spacing is achieved via `padding` on `<td>` cells (content breathing room) and spacer `<table>` rows (vertical gaps between sections). `margin` is not used for layout spacing.

---

**R9.1 — Individual Padding Properties** [MANDATORY]

Never use the `padding` shorthand on `<td>` elements. Always use the four individual properties:

```html
<!-- Correct: -->
<td
  style="padding-left:20px; padding-right:20px; padding-top:20px; padding-bottom:20px"
>
  <!-- Wrong — Outlook handles this inconsistently: -->
</td>

<td style="padding:20px"></td>
```

Most common padding pattern: `padding-left:15px; padding-right:15px; padding-top:15px; padding-bottom:15px`

---

**R9.2 — Spacer Tables** [MANDATORY]

Vertical space between sections uses explicit spacer tables — not `margin`, not `<br>`:

```html
<table
  cellpadding="0"
  cellspacing="0"
  class="separator"
  height="20"
  style="border-collapse:separate; height:20px; padding:0"
  width="100%"
>
  <tbody>
    <tr style="border-color:transparent">
      <td
        height="20"
        style="border-collapse:collapse; border-color:transparent"
      >
        &nbsp;
      </td>
    </tr>
  </tbody>
</table>
```

Both the `height` HTML attribute and `style="height:Npx"` must be set. Common heights: `10`, `20`, `30`, `35`, `50`, `60` px.

---

**R9.3 — Clearfix Div** [MANDATORY]

Every content cell must end with a clearfix div containing a non-breaking space:

```html
<div style="font-size:14px; line-height:1.5; clear:both">&nbsp;</div>
```

---

**R9.4 — Zero Margin on Block Elements** [MANDATORY]

The global style reset sets:

```css
p {
  margin: 0 0 10px;
}
h1,
h2,
h3,
h4,
h5 {
  margin: 0 0 10px;
}
body {
  margin: 0;
}
hr {
  margin: 0;
}
```

The `0 0 10px` on paragraphs provides controlled bottom spacing. Never add top margin to paragraphs.

---

**R9.5 — `word-break:break-word`** [MANDATORY]

```css
.content-cell {
  word-break: break-word;
}
```

Prevents long URLs from overflowing cell boundaries.

---

**R9.6 — `box-sizing:border-box` on Content Cell Children** [MANDATORY]

```css
.content-cell * {
  -webkit-box-sizing: border-box;
  box-sizing: border-box;
}
```

---

**R9.7 — Padding at Section Color Boundaries** [MANDATORY]

Because each section is its own table (R2.3) with its own `bgcolor`, two stacked sections can meet at a visible seam where the background color changes. Content must never sit flush against that seam.

Keep a non-zero `padding-top` **and** `padding-bottom` on the `content-cell` of every colored section (≥20px on desktop is the house default; the mobile reset in R3.4 already forces 15px on all sides, so the exposure is desktop-only). In particular, **do not** apply `content-cell padding-bottom-0` to a section immediately followed by a different-colored section, or `content-cell padding-top-0` to one that follows a different-colored section — that is exactly what makes a button or heading look glued to the next color band.

A `separator` spacer row (R9.2) does **not** fix this on its own: it is transparent, so it merely shows one side's color, and the content inside each colored block is still flush. The breathing room must live as padding **inside** each colored `content-cell`. (A transparent separator is for adding page-background gap _between_ sections — not for protecting content from the seam.)

```html
<!-- Section A: white card — real bottom padding so its last element clears the seam -->
<tr
  class="content-row"
  style="border-color:transparent; color:#333333; font-family:Arial, sans-serif"
>
  <td
    class="content-cell"
    bgcolor="#ffffff"
    style="border-collapse:collapse; border-color:transparent; background-color:#ffffff;
             padding-left:20px; padding-right:20px; padding-top:20px; padding-bottom:32px"
  >
    <!-- e.g. a CTA button — NOT flush against the next section -->
  </td>
</tr>

<!-- Section B: tinted band — real top padding so its heading clears the seam -->
<tr
  class="content-row"
  style="border-color:transparent; color:#333333; font-family:Arial, sans-serif"
>
  <td
    class="content-cell"
    bgcolor="#f7f1ea"
    style="border-collapse:collapse; border-color:transparent; background-color:#f7f1ea;
             padding-left:20px; padding-right:20px; padding-top:32px; padding-bottom:32px"
  >
    <!-- heading starts with clear space above the color change -->
  </td>
</tr>
```

## 13. Anti-Patterns — What to Never Do

These patterns are absent from all 15 templates. Their use will cause rendering failures.

---

**AP1 — No `<div>`-Based Layout Columns** [MANDATORY]

All layout uses `<table>`, `<tr>`, `<th>`, `<td>`. `<div>` appears only as: outer background wrapper, `img-wrap` containers, clearfix divs, and `mso-hide:all` mobile image wrappers.

---

**AP2 — No Flexbox or CSS Grid** [MANDATORY]

`display:flex`, `display:grid`, and related properties break layouts in Outlook.

---

**AP3 — No `float` for Layout** [MANDATORY]

`float` is not used for layout. The only occurrence is in the IE/Windows Phone media query fallback.

---

**AP4 — No External Stylesheets** [MANDATORY]

No `<link rel="stylesheet">`. All CSS is in embedded `<style>` blocks or inline. External stylesheets are stripped by most email clients.

---

**AP5 — No `<style>` After the Layout Start** [MANDATORY]

All `<style>` blocks must appear before any layout tables. Gmail strips `<style>` blocks found in the email body.

---

**AP6 — No Padding Shorthand on `<td>`** [MANDATORY]

Use `padding-left`, `padding-right`, `padding-top`, `padding-bottom` individually. Never `padding: 10px 20px`.

---

**AP7 — No `margin` for Section Spacing** [MANDATORY]

Use spacer `<table class="separator">` rows. `margin` is ignored by Outlook on most elements.

---

**AP8 — No Absolute/Relative/Fixed CSS Positioning** [MANDATORY]

`position:absolute`, `position:relative`, `position:fixed` — not supported in email layout.

---

**AP9 — No 3-Digit Hex in Inline Styles** [MANDATORY]

In `style=""` attributes, always use `#ffffff` not `#fff`. 3-digit hex is acceptable in `<style>` block rules only.

---

**AP10 — Do Not Rely on `border-radius` in Outlook** [INFORMATIONAL]

`border-radius` is applied in CSS but silently ignored by Outlook's Word renderer. Design buttons and containers so that square corners in Outlook are acceptable.

---

**AP11 — No `<p>` as Direct Child of `<table>` / `<tr>`** [MANDATORY]

Content paragraphs belong inside `<td>` or `<th>` only.

---

**AP12 — No Button Row That Fails to Stack (or Stacks With No Gap)** [MANDATORY]

Side-by-side CTAs must each live in their own `<th class="tc responsive">` so they reflow to one column at ≤640px, and each button column must carry a `padding-bottom` so the stacked buttons keep a gap. Two buttons crammed in a single cell, or `tc no-responsive` button columns, leave phones with glued or overflowing buttons. Build the desktop gutter with a `sp-hidden-mob` spacer column, not with side padding. (See R8.6.)

---

**AP13 — No Content Flush Against a Section Color Boundary** [MANDATORY]

Never zero the `padding-top`/`padding-bottom` of a `content-cell` that borders a differently colored section (e.g. `content-cell padding-bottom-0` directly above a tinted CTA band). Content butting against the seam where the background color changes reads as a layout bug — keep top/bottom padding inside each colored section. (See R9.7.)

---

**AP14 — No Media-Query-Dependent Responsiveness** [MANDATORY — IMPORTANT]

Do not let column stacking or body shrinking depend on `@media` alone (e.g. `tc responsive` columns, or a `bodyTable` that only goes fluid via `@media{table{width:100%}}`). The Gmail app strips/ignores those rules and renders the full desktop layout on a phone. Build responsiveness on inline styles that survive stripping — `display:inline-block` + `max-width` columns with MSO ghost tables, and `width:100%; max-width:Npx` inline on `bodyTable` — and use `@media` only as enhancement. Self-test by deleting the `<style>` blocks: the email must still stack to one column at phone width. (See R3.0.)

---

## 14. Quick Checklist

Pre-send verification checklist — all items are MANDATORY.

- [ ] `<meta charset="UTF-8">` and `<meta name="viewport">` at the top
- [ ] Two `<style>` blocks: first with `.sp-hidden-mob`, second with full reset
- [ ] Outer `<div>` has both `bgcolor` and `background-color` set to the same 6-digit hex
- [ ] `wrapper-table` uses `width="100%"` and `cellpadding="5"` with `class="wrapper-table"`
- [ ] `bodyTable` is fluid via inline `width:100%; max-width:600px` (with `width="600"` for Outlook) and has `bgcolor` set
- [ ] All inner tables have `border="0" cellpadding="0" cellspacing="0"` and `border-collapse:collapse`
- [ ] Every `<tr>` has `style="border-color:transparent"`
- [ ] Columns use the fluid hybrid (`inline-block` + `max-width` + MSO ghost tables) — they stack with the `<style>` blocks removed (Gmail-app safe), not `@media`-only `tc responsive`
- [ ] Button rows use the fluid hybrid with `padding-bottom` on each block, so they stack with a gap on mobile without a media query
- [ ] Deleting both `<style>` blocks still yields a clean single column at ~375px (no horizontal scroll)
- [ ] No `content-cell` sits flush against a differently colored neighbor — both sides keep non-zero top/bottom padding
- [ ] VML `<!--[if gte mso 9]><v:background...>` present on tables with `background=` attribute
- [ ] Every `<img>` has `border="0"`, `alt=""`, `display:block`, pixel `width`, `height="auto"`, `-ms-interpolation-mode:bicubic`
- [ ] Desktop/mobile image pairs use `[if !mso]><!-->`...`<!--<![endif]-->` wrapper
- [ ] Buttons use 3-table nested structure with `display:block` on `<a>` tag
- [ ] All `<td>` padding uses individual properties (`padding-left:`, not `padding:`)
- [ ] Vertical section gaps use `<table class="separator" height="N">` — not `margin` or `<br>`
- [ ] Every content cell ends with `<div style="clear:both">&nbsp;</div>`
- [ ] All `<a>` tags have `style="text-decoration:none; color:#xxxxxx"` inline
- [ ] `{{unsubscribe_url}}` present and linked in footer
- [ ] Footer includes `{{ec_es_email_sender_company}}` and `{{current_year}}`
- [ ] All inline `style` background-color and color values use 6-digit hex
- [ ] No flexbox, no grid, no `float`, no external stylesheets, no `<div>` columns
