# Internationalization — Languages, RTL, Scripts, Locale Formats

> Read this when the email is in a non-English language, mixes scripts, or targets a specific
> region. Emails reach users in any country — localization is layout + format + direction, not just
> translation. Sources: W3C i18n (qa-html-dir), Litmus community RTL threads, locale conventions.

## 1. Charset & fonts per script

- Charset is **UTF-8** (already in the document shell meta tag) — covers all scripts. Never change it.
- Use **system/email-safe font stacks** appropriate to the script; do not force a Latin web font
  onto non-Latin text (it falls back unpredictably). Web fonts are unreliable in email anyway
  (Outlook, Gmail strip them) — prefer system stacks:
  - Latin/Cyrillic: `Arial, "Helvetica Neue", Helvetica, sans-serif`
  - Arabic: `"Segoe UI", Tahoma, Arial, sans-serif` (Tahoma has good Arabic coverage)
  - Hebrew: `Arial, "Helvetica Neue", sans-serif`
  - CJK SC: `"PingFang SC", "Microsoft YaHei", "Hiragino Sans GB", sans-serif`
  - CJK TC: `"PingFang TC", "Microsoft JhengHei", sans-serif`
  - Japanese: `"Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif`
  - Korean: `"Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- placehold.co `text=` is **ASCII-only** regardless of email language — label placeholders in Latin.

## 2. RTL — Arabic, Hebrew, Persian, Urdu

**Set base direction in MARKUP, not CSS.** W3C is explicit: direction is semantic and must survive
when CSS is stripped — and email clients routinely strip/ignore CSS. Use the `dir` attribute.

- Put `dir="rtl"` on the **outer wrapper `<div>`** and on each section **`<table>`**. On a table,
  `dir="rtl"` reverses column order (first `<th>` renders on the right) and right-aligns cells.
- Set `align="right"` on cells and `text-align:right` inline as belt-and-suspenders.
- Mirror the layout: logo right, nav reversed, CTA arrows point left (←).
- Keep embedded LTR runs (URLs, emails, Latin brand names, numbers) safe with `dir="ltr"` on the
  inline element so they don't visually scramble (bidi).
- **Caveat:** Outlook desktop / Office 365 RTL handling is quirky (per Litmus community). Test the
  result; keep the structure simple (single column reflows most reliably).

```html
<div dir="rtl" bgcolor="#eeeeee" style="background-color:#eeeeee">
  <table dir="rtl" width="100%" ...>
    <tr><th align="right" dir="rtl" style="text-align:right; ...">...</th></tr>
  </table>
</div>
```

## 3. CJK — Chinese, Japanese, Korean

- Use the script-specific font stacks above; do not italicize or fake-bold CJK.
- Line length: CJK packs more meaning per character — subjects/headlines can be shorter.
- `line-height` a touch larger (≥ 1.6) for readability of dense glyphs.
- Avoid letter-spacing on CJK. Word-break differs — let the client wrap.

## 4. Cyrillic and extended Latin

- UTF-8 + standard sans-serif stack renders Cyrillic fine. Words are longer than English — give
  buttons and columns extra width and watch subject-line truncation.
- Same caution for German/Finnish/etc. (long compound words can overflow fixed-width cells).

## 5. Locale formats

Localize, don't just translate:
- **Dates:** `MM/DD/YYYY` (US) vs `DD/MM/YYYY` (most of EU) vs `YYYY-MM-DD` / `YYYY年MM月DD日` (CJK).
  When in doubt, spell the month ("12 June 2026") to avoid ambiguity.
- **Numbers:** decimal/thousands separators differ — `1,234.56` (US/UK) vs `1.234,56` (DE/much of EU)
  vs `1 234,56` (FR/RU).
- **Currency:** correct symbol and placement ("$10" vs "10 €" vs "10 zł"); don't hardcode USD for a
  EUR/UAH audience.
- **Time:** 12h (AM/PM) vs 24h; mention timezone for events.
- **Names/greetings:** order and formality vary (family-name-first in CJK; formal pronouns).

## 6. Layout cautions

- Single-column layouts survive translation length changes and RTL best.
- Leave slack in buttons/headers for languages that expand (~30% longer than English is common).
- Don't bake translated text into images — it can't be re-localized or read by screen readers.
- If sending one campaign in several languages, prefer one template per language over mixing.
